# Monitoring Contract: health-check RPS

## Экспорт

- Внутренний интерфейс: `GET /metrics` на порту `9091`, доступный Prometheus внутри сети Compose.
- Основной показатель: `cabby_gateway_health_checks_total{outcome="success|failure"}`, тип Counter.
- Оба фиксированных значения `outcome` инициализируются нулём. Каждый завершённый `GET /healthz` увеличивает ровно одну серию на единицу.
- Отдельных меток с адресами клиентов, произвольными путями, идентификаторами или текстом ошибок нет.
- Дополнительный стандартный показатель Prometheus `up{job="cabby-gateway"}` отражает успешность сбора. Ошибка соединения с gateway не увеличивает счётчик вызовов.

## Сбор и отображение

Prometheus опрашивает сервис каждые 15 секунд. Grafana использует минутное окно `[1m]`, минимальный шаг точек 1 минута, единицу `requests/second`, три линии (`success`, `failure`, `total`) и обновление каждые 15 секунд.

Для каждого исхода выражение строится по следующему образцу:

```promql
sum(
  rate(cabby_gateway_health_checks_total{outcome="success"}[1m])
  and on(job, instance) (min_over_time(up{job="cabby-gateway"}[1m]) == 1)
  and on(job, instance) (count_over_time(up{job="cabby-gateway"}[1m]) >= 4)
)
```

Для `failure` меняется значение `outcome`. Для `total` фильтр `outcome` снимается, остальные условия остаются прежними. Это позволяет суммировать экземпляры после проверки пригодности данных каждого экземпляра. После сбоя сбора точка не показывается до восстановления полного минутного окна. Порог четырёх scrape консервативен и может скрыть точку при задержке планировщика; это предпочтительнее ложного нуля.

На графике запрещены подстановка нуля вместо пустого значения и соединение разрывов линии. При работающем сборе нулевые серии дают ноль; при сбое сбора получается отсутствие данных.

`rate` оценивает среднюю частоту по периодическим снимкам счётчика и экстраполирует к границам окна. График не является точным журналом вызовов произвольной календарной минуты. Проверка SC-003 проводится на равномерной контрольной нагрузке.

## Диагностика

Ошибка обработки фиксируется структурированным сообщением с временем, именем операции и классом ошибки. Тело запроса, секреты и персональные данные не логируются. Межсервисной трассировки в первом выпуске нет, поскольку gateway не вызывает другие сервисы.
