# Implementation Plan: Опубликованный внешний контракт cabby-gateway

**Branch**: `002-gateway-external-contract` | **Date**: 2026-09-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-gateway-external-contract/spec.md`

## Summary

Опубликовать для внешних клиентов единый версионируемый контракт cabby-gateway: машиночитаемый OpenAPI 3.1 документ и человекочитаемое руководство. На текущем этапе единственная бизнес-операция — health-check (`GET /healthz`), унаследованный из спецификации 001 без изменения семантики; доступ анонимный. Контракт вводится как каркас: версионирование по SemVer (`info.version`, старт `1.0.0`), единая модель ошибок (JSON-конверт `{"error":{"code","message"}}` для отказов 404/405 и будущих операций), обнаружение операций через сам документ и политика совместимости. Сервис встраивает канонический YAML через `go:embed` и отдаёт его по новому пути `GET /openapi.yaml`; тела 404/405 переводятся с plain-text на единый конверт. Внутренний интерфейс метрик (порт 9091) не публикуется. Решения и ограничения — в [research.md](research.md).

## Technical Context

**Language/Version**: Go 1.26.1 (без изменений).

**Primary Dependencies**: Стандартные `net/http` и `embed` (`go:embed` для встроенного OpenAPI-документа); существующий `github.com/rs/zerolog` для структурированных логов. Формат контракта — OpenAPI 3.1 в YAML. Новых runtime-зависимостей не добавляется: документ отдаётся как YAML без конвертации. Для проверок — `go test ./...` и `go vet ./...`; валидация структуры, паритета и версии контракта выполняется Go-тестами без внешних npm-инструментов (OpenAPI-линтер не подключается: он тянет зависимость от недоступного реестра `artifactory.tutu.ru`).

**Storage**: N/A. Контракт — статический встроенный артефакт; бизнес-данных и хранилища нет.

**Testing**: `go test ./...`, `go vet ./...`; тесты соответствия контракту — parity отданного документа с каноническим файлом, паритет канонического файла с проектным эталоном, соответствие ответов `/healthz` (200/503) схемам, единый конверт для 404/405, отсутствие `/metrics` на публичном порту, SemVer-версия и соответствие путей роутера контракту. Нагрузочные цели health-check наследуются из спецификации 001 и не меняются.

**Target Platform**: Linux-контейнеры Docker и локальный запуск через Makefile с Go 1.26.1 (без изменений).

**Project Type**: Backend web service + опубликованный артефакт API-контракта.

**Performance Goals**: Эндпоинт контракта отдаёт небольшой статический документ — пренебрежимо малая нагрузка, read-only. Цели health-check (100 запросов/с, ≥99% ответов до 1 с) наследуются из спецификации 001 и не изменяются.

**Constraints**: Семантика health-check (200 `{"status":"ok"}` / 503 `{"status":"unavailable"}`) и счётчик метрик не меняются; доступ анонимный; контракт и тела ошибок не содержат секретов и персональных данных; внутренний интерфейс метрик исключён из внешнего контракта; единый конверт ошибок не раскрывает внутреннее устройство; OpenAPI-документ — единственный источник истины перечня операций; parity документа и реализации обязателен.

**Scale/Scope**: Один сервис, одна внешняя операция (health-check), один документ контракта, одна версия (`1.0.0`), фиксированный набор категорий ошибок (`unknown_operation`, `method_not_allowed`), расширяемый аддитивно.

### Поведение при отказах и развёртывание

- Канонический документ встраивается в бинарник (`go:embed`), поэтому `GET /openapi.yaml` не зависит от файловой системы в рантайме и всегда доступен при работающем слушателе.
- Добавление пути `/openapi.yaml` аддитивно: ранее все пути кроме `/healthz` возвращали 404, теперь документированный metadata-путь отдаёт контракт, а прочие пути по-прежнему 404 с `code=unknown_operation`. Поведение `/healthz` не меняется.
- Перевод тел 404/405 с plain-text на JSON-конверт сохраняет HTTP-коды; выпущенных клиентов нет (спецификация 001), поэтому изменение обратно совместимо и расширяет контракт 001, а не ломает его.
- Если запрошена неизвестная версия/путь, клиент получает 404 `unknown_operation`; неготовность операции health-check по-прежнему возвращается как 503 `{"status":"unavailable"}`, что отличает временную неготовность от постоянного отсутствия операции (FR-012).
- Порядок развёртывания: сначала публикуются артефакты контракта (openapi.yaml + руководство), затем код шлюза. Изменение не требует миграции данных.
- Откат: удаление обработчика контракта восстанавливает прежнее поведение «все пути кроме /healthz → 404 (plain-text)»; данные не затрагиваются.
- Паритет: тест подтверждает, что отданный документ совпадает с закоммиченным каноническим файлом, исключая дрейф между контрактом и реализацией (SC-005).


**Structure Decision**: Канонический машиночитаемый контракт размещается в `backend/cabby-gateway/api/openapi.yaml` (в пределах модуля — требование `go:embed`) и встраивается в сервис; спека `specs/002-gateway-external-contract/contracts/` хранит проектный эталон документа и руководство. Новый код — два небольших файла (`contract.go`, `errors.go`) плюс тесты; публичный обработчик эволюционирует из одиночного `http.HandlerFunc` в явный маршрутизатор по пути/методу. Внутренний обработчик метрик и его порт не затрагиваются. Каталоги web/iOS/Android не создаются.
